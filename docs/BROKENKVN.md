# BrokenKVN Bot: контракт 8a/8b

Статус: реализация и приёмка ещё не подтверждены. До заполнения реквизитов
и digest выполнение обязано останавливаться до SSH, включая --check.

## Источники и размещение

[Upstream](https://github.com/Mrvibecodic/chill-remna-bot), MIT, Go.
[Fork](https://github.com/skaryleet/chill-remna-bot): main синхронизирует upstream,
brokenkvn содержит изменения. База: ca43da07d61530242566f9abb46e0d82d4821072.
Go не vendoring в этом репозитории. GHCR: ghcr.io/skaryleet/chill-remna-bot;
service_versions.brokenkvn_bot закрепляет digest, не плавающий тег.

SW-1, группа bot, /opt/brokenkvn-bot, постоянный том bot-data. SQLite и long polling.
Контейнер работает без root, опубликованных портов, host network, SSH-ключей,
docker.sock и PANEL_CONTAINER. Обновление/откат только Ansible. Магазин upstream
сохранён; платежи/триал/Mini App/кабинет первоначально выключены.

## Конфигурация

BOT_TOKEN, ADMIN_TELEGRAM_ID=8450559575, DATA_DIR=/data, DB_KIND=sqlite.
BROKENKVN_CONFIG_FILE=/config/managed.json — JSON только для чтения:

```json
{
  "panel_url": "https://console.cormon.ru",
  "panel_token": "<из Vault>",
  "proxy_file": "/config/proxy-links.txt",
  "nodes": {"RU-1": "<uuid>", "RU-2": "<uuid>", "DE-1": "<uuid>",
            "NL-1": "<uuid>", "SW-1": "<uuid>"},
  "features": false
}
```

features=false соответствует 8a; true включает кнопки 8b. Секреты передаются
через зашифрованный .local/bot-vault.yml; пароль .local/bot-vault-password
хранится отдельно от копий и Git, права 0600. Переменные: bot_token,
bot_panel_token, bot_proxy_links. Исходный токен: .local/tg_bot; общие ссылки:
.local/telego-links-RU-2.txt. Значения не печатать и не передавать в argv.

Управляемые URL/token/SQLite имеют приоритет над базой; мастер и админка
не меняют их. Отсутствующая/битая конфигурация останавливает запуск.
Первый запуск создаёт русский интерфейс и удалённое подключение к панели;
повторный не сбрасывает магазин. Секреты не отражаются в логах и diff.

Отдельный API-токен: обязательный минимум upstream для магазина/кабинета,
права hwid-user-devices:list-by-user, hwid-user-devices:delete-all, nodes:list.
Без wildcard и node-plugins:executor. Операторский .local/api_token не выдаётся боту.

## Поведение

8a: кабинет VPN, сохранённый магазин и административная рассылка.
Telegram ID берётся из отправителя Bot API; ответы только в личном чате.
Remnawave 3 users/stream обходится по nextCursor; каждая запись проверяется
по telegramId. Несколько разных записей блокируют выдачу и мутации аккаунта;
ошибки поиска не разрешают создание дубликата. Рассылка — только администратору.

8b: Telegram Proxy выдаёт только готовые общие ссылки RU-2. В файле допустимы
пустые строки, комментарии #, tg://proxy?... и https://t.me/proxy?...;
server=ru-ae.cormon.ru, port=2053, непустой корректный MTProto secret.
Ссылки сохраняются без преобразования, персональные секреты не генерируются,
бот не изменяет telego_secrets и не подключается к telEgo. Файл — read-only;
обновление через Ansible с перезапуском. Ошибка файла означает недоступность.

Proxy и статус требуют единственной ACTIVE-подписки с будущим expireAt.
Авторизация проверяется при каждом callback, включая старые кнопки.
Ошибка API, истечение срока, блокировка и неоднозначность закрывают доступ.

Статус: GET /api/nodes каждые 60 секунд, timeout 5 секунд, stale после 180 секунд.
Пять узлов сопоставляются по UUID. Показываются подключён/не подключён/отключён/
нет данных, источник «по данным панели» и время получения в МСК.
Ошибка обновления и возраст последнего снимка видимы. До первого успешного
опроса — нет данных. Это не клиентская проверка VPN; адреса и внутренние ошибки
панели пользователю не выдаются. Локальный monitoring не изменяется.

## Выполнение и откат

bot.yml допускает ровно SW-1 и явный bot_deploy=true. Реквизиты, конфигурация,
топология и digest проверяются до SSH. Остальные предохранители сохраняются.
Перед apply проверить ресурсы, Docker/Compose, доступ к Telegram/GHCR/панели.
Секретные задачи: no_log, diff=false. Повторный apply: changed=0.

Перед обновлением остановить бот, сохранить полный bot-data (bot.db,
secret.key и вспомогательные файлы), возобновить работу. Зашифровать архив
Ansible Vault и сохранить вне SW-1 в .local/backups/brokenkvn-bot/.
Не обновлять до подтверждения внешней копии. Восстановление проверять в
изолированном томе без Telegram poller. Откат: предыдущий digest и, при
несовместимой миграции, соответствующий снимок данных. Ежедневное резервирование
отложено до этапа эксплуатации. Пароль Vault не хранить вместе с копиями.

## Проверки и приёмка

Docs → tests → implementation. Go: конфигурация, пагинация/неоднозначность,
ошибки API, callback-авторизация, Proxy, stale/ошибка/отсутствие узла;
go test ./..., go test -race ./..., сборка контейнера.
Ansible: неверный хост/пустой digest/реквизиты/битые ссылки завершаются до SSH
в обычном и check-режиме; непривилегированный Compose; make check.
Исходная блокировка yamllint: лишняя пустая строка european.yml — удалить отдельно.

8a: администратор входит, пользователь видит только свою подписку,
неадминистратор не рассылает, платежи выключены, повторный apply changed=0.
8b: ссылки совпадают с источником, неактивному доступ закрыт, показаны пять
узлов и метка времени; ошибки/stale воспроизводятся в тестовом окружении.
Перезапуск сохраняет данные; внешняя копия восстановлена; новые публичные
порты не появились, VPN/Proxy-сервисы не изменились. Telegram-приёмку выполняют
администратор и тестовые пользователи; автоматическая рассылка не требуется.
Отчёт фиксирует автоматические проверки отдельно от пользовательской приёмки.
